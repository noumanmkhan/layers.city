# Raw data: where each file in `raw/` came from

All files were fetched on 2026-10-06.

| File | Source |
|---|---|
| `city_bundle1.json` | City of Toronto ArcGIS REST services at `https://gis.toronto.ca/arcgis/rest/services/`, queried with `query?where=1=1&outFields=*&outSR=4326&f=geojson&geometryPrecision=5&maxAllowableOffset=0.00004` (0.00003 for roads), paged with `resultOffset`. Holds `formermun` (cot_geospatial27/MapServer/6, Former Municipality), `wards` (cot_geospatial26/MapServer/0, City Ward), `provexp` (cot_geospatial/MapServer/4, Provincial Expressway), `cityexp` (cot_geospatial/MapServer/5, City Expressway) and `prov` (cot_geospatial28/MapServer/9). `prov` is not used because it holds the pre-2018 ridings. |
| `streets.json` | Fetched by `fetch_streets.py` (run by the *Fetch street centrelines* GitHub Action) from the same City GIS service: the Major Arterial, Minor Arterial and Collector layers of `cot_geospatial/MapServer`. Collectors are drawn on their own layer (`streets.py` → `collectors.geojson`), leaving out stretches that sit on a main street. |
| `nbhd158.geojson` | City of Toronto Open Data, "Neighbourhoods" (158, 4326 GeoJSON) |
| `nbhd140.geojson` | City of Toronto Open Data, historical 140-neighbourhood boundaries (used only to define the Old Toronto areas) |
| `bia.geojson` | City of Toronto Open Data, "Business Improvement Areas" (85 features) |
| `heritage_districts.geojson` | City of Toronto Open Data, "Heritage Conservation Districts" (shapefile, refreshed quarterly; fetched 2026-10-07 by `.github/workflows/fetch-heritage.yml`). `heritage.py` keeps the 29 with type "Designated District" and drops the ones "Under Study" or "Under Appeal". A designation date of 1899-11-30 means none recorded |
| `fed2023.geojson` | Open North Represent: `/boundaries/federal-electoral-districts-2023-representation-order/simple_shape`, filtered to the Toronto area |
| `prov2015.geojson` | Open North Represent: `/boundaries/ontario-electoral-districts-representation-act-2015/simple_shape`, filtered to the Toronto area. Used for riding names; the geometry comes from the wards. |
| `ttc_rapid_routes.geojson`, `ttc_rapid_stops.geojson` | Lines 1, 2, 4, 5 and 6 extracted from github.com/Miqell24/toronto-bus-map (`docs/data/route.geojson`, `stops.geojson`), which is built from the TTC's Merged GTFS feed |
| `neighbours/*.geojson` | OpenStreetMap municipal boundary relations for all 24 municipalities in the Halton, Peel, York and Durham regions (via github.com/missinglink/osm-boundaries) |
| `lakes.geojson` | Natural Earth 10m lakes: Ontario, Erie, Huron, Georgian Bay, Simcoe and Scugog. Used for the regional view only outside the box that `gta_lakes.geojson` covers: its shore runs up to 1–2 km inland, which put Port Credit in the lake. |
| `gta_lakes.geojson` | OpenStreetMap (ODbL) via the Overpass API: the Lake Ontario (r1206310), Lake Simcoe and Lake Scugog water relations, joined into polygons, clipped to -80.8–-78.0° W, 42.9–44.9° N and simplified to about 5 m. Fetched 2026-10-10 by `.github/workflows/fetch-gta-shoreline.yml` running `fetch_gta_shoreline.py`; the log is `fetch_gta_shoreline.log`. `build.py` cuts the neighbouring municipalities to this shore. |
| `landwater.geojson` | City of Toronto, Toronto Land And Water Area (cot_geospatial27/MapServer/40). Areas coded 2xxx are land (the mainland and each island) and 1xxx are water (Toronto Harbour, Grenadier Pond and others). Every boundary layer is clipped to the land areas so nothing is drawn over the lake or harbour. |
| `gta_motorways.json` | OpenStreetMap (ODbL) via the Overpass API: every `highway=motorway` way in the map's box, fetched by `.github/workflows/fetch-gta-highways.yml` running `fetch_gta_highways.py`. Used only for the parts of the 400-series, QEW and 407 outside Toronto. |
| `gta_places.json` | OpenStreetMap (ODbL) via the Overpass API: every named `place` of type town, village, hamlet, suburb, quarter or neighbourhood in the GTA's box (points, or the centre of areas), fetched by `.github/workflows/fetch-gta-places.yml` running `fetch_gta_places.py`. `gta_places.py` keeps those inside the 24 surrounding municipalities (tested against `neighbours/`) for search suggestions. |
| `go_routes.geojson`, `go_stops.geojson` | GO Transit rail lines, UP Express and their stations, extracted from github.com/Miqell24/toronto-bus-map (`docs/data/route.geojson`, `stops.geojson`), which is built from Metrolinx's GO and UP GTFS feeds |
| `neighbourhood_profiles_2021.xlsx` | City of Toronto Open Data, "Neighbourhood Profiles", 2021 Census 158-neighbourhood model (`nbhd_2021_census_profile_full_158model.xlsx` from `ckan0.cf.opendata.inter.prod-toronto.ca`), fetched by `.github/workflows/fetch-profiles.yml` running `fetch_profiles.py`. `neighbourhood_profiles_resources.txt` lists every file in that dataset at fetch time. `profiles.py` reads tenure, median dwelling value, median rent and main mode of commuting from it. |
| `transit_union.json` | Computed by `fetch_transit_union.py` (run by the *Compute transit times to Union* GitHub Action) with r5py: weekday 8–9 am trips to Union Station from about 4,000 points across the 158 neighbourhoods. Inputs: TTC schedules (City of Toronto Open Data, "TTC Routes and Schedules"), GO Transit and UP Express GTFS (Metrolinx Open Data), and OpenStreetMap for walking (Geofabrik Ontario extract, cut to the Toronto area). The exact URLs and the departure date are recorded inside the file. |
| `representatives/` | Fetched every Monday by `fetch_representatives.py` (the *Refresh representatives* GitHub Action): `ourcommons.xml` from `https://www.ourcommons.ca/Members/en/search/XML` (current MPs), `ola.html` from `https://www.ola.org/en/members/current` (current MPPs), and `toronto.json`, the page title of each `https://www.toronto.ca/city-government/council/members-of-council/councillor-ward-N/` (current councillor for ward N), and `mayor.json`, the page title of `https://www.toronto.ca/city-government/council/office-of-the-mayor/about-mayor/` ("Olivia Chow, 66th Mayor of Toronto"; the first copy was typed in from that title on October 16, 2026, because toronto.ca can't be reached from the build sandbox). `representatives.py` matches them to the map's wards and ridings. |
| `school_wards_2026.json` | Typed in from the City Clerk's "2026 Municipal Election – School Board Reference Chart" (updated April 23, 2026, `https://www.toronto.ca/wp-content/uploads/2026/04/9600-2026-School-board-ward-reference-chart.pdf`), which lists each trustee ward of the four boards (TDSB, TCDSB, Conseil scolaire Viamonde, Conseil scolaire catholique MonAvenir) as a set of City wards. `school_wards.py` merges the City wards into trustee wards. The City's open "Elections - School Ward" dataset was not used: it holds the 2018 lines, and TDSB went from 22 wards to 12 in April 2026. |
| `representatives/results.json` | The City's election results file, `https://mediaresults.toronto.ca/results/unofficialresult.json` (spec: "JSON Unofficial Result Files Data Specifications", v1.1, September 2026), fetched with the representatives. Lists every 2026 candidate by office and ward; on election night it fills in the votes. Used for the school trustee rows, the council races and the mayoral race. |
| `skyscrapers/wiki.json` | English Wikipedia, "List of tallest buildings in Toronto" (CC BY-SA 4.0): every table on the page with its section, cell text and article links, each linked article's coordinates and Wikidata id (Wikipedia API), and the street addresses in `skyscrapers.json` geocoded with OSM Nominatim. Fetched by `.github/workflows/fetch-skyscrapers.yml` running `engine/fetch_skyscrapers.py` (monthly, or when the script or `skyscrapers.json` changes). `engine/skyscrapers.py` builds `skyscrapers.geojson` from it and `skyscrapers.json` (towers left out, which of this year's towers are open, hand-placed coordinates, former names, curated facts). |
| `institutions_osm.json` | OpenStreetMap (ODbL) via the Overpass API: every university, college and hospital in and around Toronto, plus a few campuses and hospitals by name that OSM doesn't tag as amenities. Fetched 2026-10-10 by `.github/workflows/fetch-toronto-institutions.yml` running `fetch_institutions.py`. `institutions.py` holds the curated list (rules in its header) and takes each point's position from here. |
| `faith/worship_osm.json` | OpenStreetMap (ODbL) via the Overpass API: every named place of worship in and around Toronto, with religion and denomination tags. Fetched by `.github/workflows/fetch-toronto-faith.yml` running `fetch_faith.py`. `faith.py` keeps one point per place and applies `faith_overrides.csv` (hand-kept additions, fixes and removals; OSM misses storefront congregations and new buildings). |
| `faith/geocode.json` | OpenStreetMap Nominatim: positions for the addresses in `faith_shops.csv` and the additions in `faith_overrides.csv`, cached so each address is looked up once. Same workflow. `faith_shops.csv` is curated by hand from the certifiers' public lists: HMA's certified stores (halal) and COR's directory (kosher), independents only, each shop once with its roles (grocer, butcher, bakery); chains with a halal or kosher counter, wholesalers and restaurants are left out. |
| `schools/ontario_schools.csv` | Ontario Ministry of Education, "School information and student demographics" (Ontario Data Catalogue, `data.ontario.ca/dataset/school-information-and-student-demographics`), Open Government Licence – Ontario. `fetch_schools.py` (GitHub Actions, `fetch-toronto-schools.yml`, twice a year) picks the newest English school-year file (2024–25, published September 2026) and keeps only descriptive columns (board, school, level, grade range, language, address, website, coordinates) for schools in a box around Toronto; test results and student demographics are dropped before anything is written. `ontario_schools.meta.json` records the file and its school year. |
| `schools/school_locations_4326.csv` | City of Toronto Open Data, "School locations - all types" (`School locations-all types data - 4326.csv`, refreshed 2026-05-27), downloaded by hand on 2026-10-14 (the portal blocks the sandbox). Used only for each school's point. The file is out of date on the French boards: it files six of their newer schools under English boards or as private, so `french_schools.py` matches by name and address, never by its board field. `french_schools.csv` is curated by hand from the boards: TDSB's 2026-27 Early and Middle French Immersion location maps (`tdsb.on.ca`, French Programs, Locations & Maps), TCDSB's French as a Second Language page (`tcdsb.org/o/teachingandlearning/page/french`), and the Viamonde and MonAvenir school lists. Bannockburn PS (TDSB Early Immersion) isn't in the City's file yet and is left out. |
| `nearby/parks_rec.geojson`, `nearby/tpl_branches.json` | City of Toronto Open Data: "Parks and Recreation Facilities" (Parks, Forestry & Recreation, refreshed monthly; 1,802 parks and centres with listed amenities) and "Library Branch General Information" (Toronto Public Library, 112 branches). Fetched by `.github/workflows/fetch-toronto-nearby.yml` (monthly) running `fetch_nearby.py`; `nearby.py` builds `docs/toronto/data/nearby.json` for the card's Nearby section. The parks list names no pools or rinks; those come from the next row. |
| `nearby/rec_facilities.json` | City of Toronto Open Data: "Registered Programs and Drop In Courses Offering" (Parks, Forestry & Recreation, refreshed weekly), its Facilities tab (9,908 rows, one per facility: each pool tank, ice pad, diamond, field and court, with its FacilityType) and Locations tab (1,884), trimmed to ids, type, name and address. Fetched with the parks list by `fetch_nearby.py`. `sports.py` builds `docs/toronto/data/sports.geojson` for the Sports & rec layer: pools (indoor and outdoor tanks, shown as one pool), rinks (indoor and outdoor ice pads, skating trails), ball diamonds, fields (soccer, football, rugby, multipurpose), tennis, basketball, skateparks and cricket, plus pickleball from the parks list's AMENITIES (the Facilities tab has no pickleball type). Locations are placed by the parks list's LOCATIONID, else their parent location, else a same-named City outline; 592 placed, 13 left out (school yards, hydro fields, unnamed rows). Some facilities are missing from the City's list (e.g. the Regent Park Aquatic Centre pool, October 2026). |
| `nearby/green_spaces.geojson`, `nearby/water_play_osm.json` | City of Toronto Open Data: "Green Spaces" (Geospatial Competency Centre with Parks, Forestry & Recreation; 3,381 areas, trimmed to name, class and id). `parks.py` keeps AREA_CLASS "Park" (1,629 City parks; no cemeteries, golf courses, hydro corridors or TRCA land) for the Parks layer, `docs/toronto/data/parks.geojson`, matching each parks-list entry to its outline (same name within 300 m, else the outline it sits in, else the nearest within 40 m: 1,509 of 1,519 matched). The City's list names no splash pads or wading pools, so those come from OpenStreetMap (ODbL, Overpass: `leisure=splash_pad`, `playground=splash_pad`, wading pools), placed in a park the same way; OpenStreetMap misses some. Fetched with the parks list by `fetch_nearby.py`; the workflow also rebuilds `parks.geojson`. |
| `nbhd_region.json` | Generated by `regions.py` |
| `drive_points.json`, `drive_times.json` | The suburban lens: `engine/drive.py points toronto` lays a grid about 1.5 km apart over the municipalities around the city; `engine/fetch_drive_times.py` (the *Fetch drive times* GitHub Action) times each point by car to Union Station with OSRM's public server on OpenStreetMap roads, free-flow, and drops points more than 1 km from a road. Fetched on 2026-10-07. |
| `construction/osm.json` | OpenStreetMap (ODbL) via the Overpass API: rail lines, stations and routes tagged as under construction in the regional box. Fetched by `.github/workflows/fetch-construction.yml` (monthly, or when the script changes) running `engine/fetch_construction.py`; `inventory.txt` lists what came back. `engine/construction.py` keeps only the projects in `construction.json`. |
| `closures/permits.json` | the City of Toronto's live Road Restrictions feed, `https://secure.toronto.ca/opendata/cart/road_restrictions/v3?format=json` (Open Data dataset "Road Restrictions", Transportation Services, real time). Kept: permits filed as Metrolinx, plus permits from the transit consortiums listed in `construction.json`. The feed isn't strict JSON (stray backslashes), so `fetch_closures.py` escapes them first. Fetched daily just after midnight Eastern by `.github/workflows/fetch-closures.yml` running `fetch_closures.py`, which then runs `engine/closures.py` to write `docs/toronto/data/closures.geojson`. The log is `closures/fetch.log`. |
| `closures/events.json` | the same Road Restrictions feed, records with `specialEvent` = "Yes" (races, parades, festivals, block parties), written by the same daily `fetch_closures.py` run. The organizer is the record's contractor (the Waterfront Marathon's are "Canada Running Series Inc."); a closure is a curb lane only when its name says "curb lane", since the description boilerplate says all lanes even then. `engine/events.py` groups them into events (names from `events.json`) and writes `docs/toronto/data/events.geojson`. Where the feed disagrees with the police's closure notice, `events.json` "corrections" retime or drop its closures and add the stretches it leaves out, traced along `raw/streets.json`; each such closure says so in its text (Waterfront Marathon 2026: [Toronto Police release](https://www.tps.ca/media-centre/news-releases/67138/)). |
| `events/twm-marathon-course.gpx` | The Waterfront Marathon course: Canada Running Series' official Garmin course (connect.garmin.com/modern/course/401712199, linked from torontowaterfrontmarathon.com/event-info as "Garmin course marathon"; its metadata still says 2025, but it is the course linked for 2026 and follows the 2026 closures). Added by hand once per race; `events.json` `courses` points to it and limits it to that year's race. `engine/events.py` scales distance along it to the official 42.195 km for the kilometre marks. |
| `surface/routes.json`, `surface/stops.json` | Fetched by `engine/fetch_surface.py` (the *Fetch streetcar and bus routes* GitHub Action, monthly) from the TTC GTFS from City of Toronto Open Data (CKAN package `ttc-routes-and-schedules`), source in `cities/toronto/surface.json`. Streetcar and bus routes only (route numbers in `skip` are drawn by the rapid-transit layer): the shapes carrying at least 10% of a direction's trips over the coming week, simplified to about 5 m; trips per hour of first departure on one weekday, one Saturday and one Sunday; every stop with the routes serving it that week. The feed URL, the week used and the fetch date are recorded in the files; `surface/fetch.log` is the run's log. Built into the map by `engine/surface.py`. |
| `surface/go/routes.json`, `surface/go/stops.json` | GO Transit bus routes and stops, fetched by the same Action (`engine/fetch_surface.py toronto go`) from Metrolinx's GO GTFS, `https://assets.metrolinx.com/raw/upload/Documents/Metrolinx/Open%20Data/GO-GTFS.zip` (Metrolinx Open Data, Open Government Licence – Ontario – Metrolinx; the same file `fetch_transit_union.py` uses). Buses only (GO trains come from `go_routes.geojson`); route numbers prefixed "GO ", shapes simplified to about 13 m. `engine/surface.py` adds them to `transit.json` and `transit_routes.geojson` with mode `go` and no families, and marks the routes with a stop in Toronto. `surface/go/fetch.log` is the run's log. Scouting: `scouting/scout_go_buses.log` and `scouting/go_buses/`. |

The City's GIS server rejects bursts of parallel requests, so fetch one layer at a time.

## Tree canopy
`raw/canopy/canopy.json`: share of each neighbourhood's land under tree cover (water left out), from ESA WorldCover 2021 v200 (10 m, CC BY 4.0, https://esa-worldcover.org), the tiles fetched from `esa-worldcover.s3.eu-central-1.amazonaws.com` by `engine/fetch_canopy.py` in the *Fetch tree canopy* Action (`fetch-canopy.yml`, on change or by hand); `raw/canopy/fetch.log` is its log. `engine/canopy.py` adds `canopy` and `canopyBand` to the profiles (cuts in `canopy.json`).

## What's changing
`raw/changes/devapps.json`: City of Toronto Open Data "Development Applications" (CKAN `development-applications`, the datastore CSV): Community Planning applications (rezoning OZ, site plan SA, subdivision SB, condominium CD, part lot PL), kept when submitted in the last two years or not closed; X/Y converted from MTM zone 10 (NAD27, EPSG:2019). Planner contact fields are dropped. `raw/changes/permits.json`: "Building Permits - Active Permits" and "- Cleared Permits" (since 2017), new buildings and demolitions that aren't houses, one row per permit (latest revision, original description), placed on "Address Points (Municipal)" (EPSG:4326 CSV) by GEO_ID, else by street address (about 9% can't be placed and are left out); builder names are dropped. Both fetched weekly by `engine/fetch_changes.py` (*Fetch what's changing* Action, `fetch-changes.yml`); `raw/changes/fetch.log` lists types and statuses. Filters and stages: `changes.json`.

## Heritage buildings
`raw/heritage_buildings.json`: City of Toronto Open Data "Heritage Register" (CKAN `heritage-register`, the address points shapefile, refreshed quarterly), only records with STATUS "Part IV" (designated one by one under the Ontario Heritage Act), with the fields the map uses. Fetched monthly by `engine/fetch_heritage_buildings.py` (*Fetch heritage buildings* Action); `raw/fetch_heritage_buildings.log` lists every field and status. `engine/heritage_buildings.py` keeps one point per property (its primary address) and takes a name from the start of the description when there is one.

## Bike lanes
`raw/bikes.geojson`: City of Toronto Open Data "Cycling Network" (CKAN `cycling-network`, the newest WGS84 GeoJSON resource), with the fields the map uses. Fetched monthly by `engine/fetch_bikes.py` (*Fetch bike lanes* Action); `raw/fetch_bikes.log` lists the fields and how many segments of each type. `engine/bikes.py` sorts each segment's higher-order facility (INFRA_HIGHORDER) into the classes in `bikes.json`; a type not listed there is left out and printed. No licence is stated on the package (portal terms apply): on the commercial re-check list.

## Bike Share stations
`raw/bikeshare.json`: Bike Share Toronto's GBFS feed (run by the Toronto Parking Authority; `gbfs.json` at tor.publicbikesystem.net, linked from the City's open data package `bike-share-toronto`): `station_information` (name, position, capacity, configuration, e-bike charging, rental methods) plus whether each station is installed from `station_status`. Live bike and dock counts are not kept. Fetched weekly by `engine/fetch_bikeshare.py` in the *Fetch bike lanes* Action; `raw/fetch_bikeshare.log` counts stations by configuration and payment methods. `engine/bikeshare.py` (config `bikeshare.json`) builds `docs/toronto/data/bikeshare.geojson`. The portal package says "License not specified" and the feed gives no licence URL: on the commercial re-check list.

## Voting places
`raw/voting/subdivisions.geojson` and `raw/voting/places.geojson`: the City Clerk's voting subdivisions (polygons) and election-day voting places (points) for the 2026 municipal election, from the City's ArcGIS Online feature services `COTGEO_VOTING_SUBDIVISION` and `COTGEO_VOTING_LOCATION` (`services3.arcgis.com/b9WvedVPoizGfvfD`), linked from https://www.toronto.ca/city-government/elections/city-elections/voting-places/ ("subject to change up to and including election day"). Joined on the code ward (2) + subdivision (3): `AREA_LONG_CODE` = `POINT_LONG_CODE`, one place per subdivision (1,356 in October 2026). `raw/voting/list.xlsx`: the "List of Voting Places (All Wards)" spreadsheet from the same page, for building names, entrances and accessibility notes, used only where its address agrees with the point (the points are edited more recently). `raw/voting/meta.json`: each layer's last edit time (the card's "as of"). Fetched daily in October by `fetch_voting.py` (*Fetch voting places* Action, `fetch-voting.yml`); `raw/voting/fetch.log` is its log. Built by `voting.py`. No licence is stated on these layers or the earlier years' "Elections Voting Locations" dataset on the open data portal: on the list to re-check before any commercial feature.

## Collection day
`raw/collection/areas.geojson`: the City's GIS layer "Residential Waste Collection Schedule" (`gis.toronto.ca/arcgis/rest/services/cot_geospatial21/MapServer/3`, 51 polygons; `AREA_NAME` is the calendar, e.g. "Wednesday1", and two areas downtown are "No Collection"). The live layer behind the City's own lookup; the CKAN shapefile of the same areas (`solid-waste-daytime-curbside-collection-areas`) dates from 2019 and has 34. No licence is stated on the GIS layer: on the commercial re-check list.
`raw/collection/schedule.csv`: Toronto Open Data "Solid Waste Collection Schedule" (CKAN `solid-waste-pickup-schedule`, Open Government Licence – Toronto), the newest `pickup-schedule-<year>` resource. One row per calendar per pickup date: `WeekStarting` is the pickup day itself (holiday weeks move it), and each stream's flag is the day's letter (T, W, R, F) or 0. Covers houses and buildings under 9 units with daytime curbside collection.
Fetched monthly by `fetch_collection.py` (fetch-toronto-collection.yml), which also runs `collection.py` → `docs/toronto/data/collection.geojson`. **Yearly swap:** the fetch takes the newest year on CKAN; the City usually publishes the next year's calendar by March, so from January until then the card says the calendar has run out.

## Parking
Fetched into `raw/parking/` by `fetch_parking.py` (*Fetch Toronto parking* Action, `fetch-toronto-parking.yml`, monthly on the 3rd, on change or by hand; `raw/parking/fetch.log`), then built by `parking.py` into `docs/toronto/data/parking.geojson`, `permit_areas.geojson` and the `permit`/`permitBand` profile fields.
- `greenp.json`: City of Toronto Open Data "Green P Parking" (CKAN `green-p-parking`, the `green-p-parking-2019` JSON). The newest the City publishes; the package is marked "Will not be Refreshed". 252 car parks (32 garages, 220 surface lots), 35,759 spaces. Notices of the day in the addresses ("reduced parking", "closed for construction until November 2019") are dropped; rates and monthly permits are left out because they have changed. Green P's own website has a car park API (key embedded in its page script, behind bot protection); it isn't published as open data, so it isn't used.
- `greenp_osm.json`: OpenStreetMap car parks with operator Toronto Parking Authority / Green P (ODbL, Overpass), only to log how many 2019 lots still have one within 150 m (151 of 252 in October 2026). OpenStreetMap lacks many lots that certainly exist (St. Lawrence Garage, the Lake Shore park lots), so it can't prune the list.
- `permit_areas.geojson`: City of Toronto Open Data "On-Street Permit Parking Area Maps" (CKAN `on-street-permit-parking-area-maps`, the WGS84 GeoJSON), 97 areas named by code (`AREA_NAME`, e.g. "12B"); every other field is empty. Areas only: which streets inside an area allow permit parking is in the Traffic and Parking by-law schedules (CKAN `traffic-and-parking-by-law-schedules`), not used yet.
- `ev_city.geojson`: City of Toronto Open Data "City Operated Electric Vehicle Charging Station Map" (CKAN `city-operated-electric-vehicle-charging-station-map`): 82 on-street and Green P sites with Level 2 and Level 3 port counts. Used only where the AFDC list has no charger within 40 m.
- `ev_afdc.json`: the Alternative Fuels Data Center station API (U.S. Department of Energy; the same listings as Natural Resources Canada's Electric Charging and Alternative Fuelling Stations Locator), `fuel_type=ELEC&country=CA&state=ON`, kept to a box around the city. The API moved from `developer.nrel.gov` to `developer.nlr.gov` when the lab was renamed; the fetch tries both. Uses the `NLR_API_KEY` repository secret if set, else `DEMO_KEY` (enough for one call a month). Fields kept: name, address, position, access, status, hours, port counts by level, connectors, network, price, charging units (connectors with ports only), dates. `parking.py` keeps public, unrestricted, open or temporarily unavailable stations inside the City; joins a garage's units listed one by one; titles points by address where the name is an operator's. NRCan's own map service (`maps-cartes.services.geo.ca/.../NRCan/electric_charging_alternative_fuelling_stations`) was last updated in 2022, so it isn't used.
- Licences: the City's packages say "License not specified" on the portal (Open Government Licence – Toronto is the portal's licence); AFDC data is public under the API's terms of use. All on the commercial re-check list.
